## 标注、区域校准与纠错

```powershell
& .\.venv\Scripts\python.exe -m app.cli calibrate data/screenshots/user-251228-hidden-start/00000001.png
```

左侧显示原图和区域，右侧可以滚动。拖框建立目标，选择牌种或输入文字；“调整区域”模式拖框更新相对坐标。旋转角度表示逆时针转正方向。手牌和摸牌区域分别处理。

点击已有标注或识别框可选中目标，修改牌种、文字、按钮状态、副露组和来源后点击“应用修正”。标注保存到原图旁的 `.annotation.json`；更正另追加到 `.annotation.corrections.jsonl`，保留修改前后值。原始图片保持不变。

每张图片填写对局编号和划分 `train/debug/test`。同一对局不能跨集合。核对后勾选“本图标注已人工核对”；“核对区域完整性”记录哪些区域已标注全部目标，包括确实为空的区域。模板仅从经过核对的 `train` 对局构建。未核对的自动识别框不能当作验收真值。

动画、遮挡等不确定图通过“核对暂停证据区域”填写受到影响的区域，保存为 `expected_pause_regions`，例如 `hand, score_self`。完整性或暂停证据发生修改时，需要重新勾选“已人工核对”，更正日志保留修改前后值。工具读取图片旁的原始 `.frame.json` 并传给识别器，保留采集时的质量警告；人工标注不能自动消除原始采集警告。

调整区域会移除旧的槽位和网格配置；调整手牌或摸牌也会使旧的联动布局失效，防止识别器覆盖用户的新坐标。牌河网格 `grid` 支持 `origin/pitch/tolerance`；倾斜的左右牌河使用 `anchor=center` 和两条 `basis` 基向量，按实际位置投影到行列，保留吃碰后的空位。没有网格、位置冲突或超出容差时仍待确认。区域边缘的裁切碎片另保存于 `boundary_fragments`，在 GUI 中可点击修正，保留原图位置并暂停该区域，不算作已确认空区域。可信匹配的可见蓝色牌背作为负例排除，不给出其暗手牌种。

`hand_layout` 根据已校准牌槽、牌体上下检测带和可见间隔分离摸牌，支持副露后 10、7、4、1 张常规暗手右侧的摸牌。较小的副露不能仅因白色像素较多就被认作完整手牌；缺牌、遮住间隔或无法确定布局时保留待确认。此处只处理画面位置，不推断摸牌历史。

相邻副露的牌种只有一个合法三张/四张划分时才分组。`chi_source_by_called_position` 与 `pon_source_by_called_position` 分别定义转正后的横牌位置到来源玩家的映射，只有已知合法三张组且恰有一张横牌时使用；未知牌种、多横牌及未确定杠结构不输出确定来源。三组独立回放的碰已用公开弃牌消失和副露出现的序列核对，与 [WRC 规则 §8.12](https://www.worldriichi.org/s/WRC_Rules_2022_20220708_site.pdf) 的摆放约定一致，证据见 `reports/vision/meld-source-review.json`；此处玩家编号为当前视角的相对编号，不冒充第三阶段的引擎座位同步。

动画中的大块亮色前景如果尺寸超出牌体，保存为 `unresolved_components`；预览和 GUI 显示未知框，可点击查看。只有与本区域 train 负例可信匹配的可见蓝色牌背可排除，其它大块前景仍暂停；牌背不计入已知牌实例，不推断隐藏身份。自己的副露区域与暗手重叠时，在检测掩码里排除已定位的完整暗手／摸牌槽，原图及分类裁切像素保留。局部背景、裁切或杠重叠仍可能待确认，不能靠这些框自动填牌。

## 构建模板、运行静态识别和评估

```powershell
& .\.venv\Scripts\python.exe -m app.cli templates data/screenshots/user-251228-calibration/00000001.annotation.json --output assets/templates/example/manifest.json
& .\.venv\Scripts\python.exe -m app.cli recognize data/screenshots/user-251228-hidden-start/00000001.png --output reports/vision/my-frame.json
& .\.venv\Scripts\python.exe -m app.cli vision-evaluate data/screenshots/user-251228-calibration/00000001.annotation.json
```

识别导出 JSON 和 `.overlay.png`，包含牌框、可见牌面四边形、区域、匹配分数、替代候选、模板清单 SHA-256、特征版本和错误原因。低分、近似并列、缺少对应区域模板、文字格式或数值范围无效均输出未知。整牌特征保留 BGR，并按背景亮度校正高亮色偏；另从当前裁切提取白色牌面四边形，透视校正后对齐彩色字形，保留普通五与赤五的区别。37 类训练字形齐全时可跨物理区域比较，蓝色牌背仍限于已标注区域；尚无素材的组合选择不能仅凭共享特征接受。整牌与字形证据冲突时输出未知。白板必须有可信空白牌面，浅色纹理不能被忽略成白板。牌体轮廓若实测存在明显梯形（对边长度相对差达到阈值）或拟合四边形成立，则先做单应性校正再分类；直立矩形的牌面不重采样。校正只改变分类器输入，颜色与朝向证据仍使用原始裁切像素。

默认特征版本为 `bgr-body-v2-and-rectified-colour-glyph-v4`。原 v3 白色轮廓有效时沿用其特征；仅当轮廓失败时，回退亮度阈值为 0.84，并要求有效四边形覆盖裁切至少一半。这样处理斜向反光，不全面放宽分类分数。历史 v3 仍使用原来的 0.94 白色轮廓配方；各版本的完整参数保存在清单，版本未知、参数不一致或模板校验失败停止加载。新位图按内容校验值命名，构建前后保存 `manifest-<SHA256>.json` 副本，已有位图和副本不覆盖。仅有旧模板副本不能保证复现当时整条链路，缺失副本不事后补称为历史原件。

视觉 SVM 作为已有未知候选的校验器，使用 OpenCV CPU 的 HOG、颜色和行列投影特征。模型只从已核对 train 手牌/摸牌训练，派生缩放、透视和色偏不计为新增真实数据；公共 train 牌用于开发检查，冻结后才读取 test。运行时三组模型必须与既有模板候选一致，候选分数至少 0.75；已知整牌/字形冲突、不可校正牌面和白板空白条件不能由投票解除。模型投票不是概率。先前报告中横置三万被识别成六万的“错误”，经放大原图与已有三万/六万素材核对，确认是 test 标注把六万转录成三万；该项已更正并保留原始报告与更正日志，模型及训练数据未变。当前冻结模型裁切诊断未发现已知错牌，但样本很小，不证明概率校准或总体精度，运行时校验条件保留。证据见 `reports/vision/called-six-label-correction.json`。模板和模型的牌面配方、版本、来源划分、OpenCV 版本及校验值均须一致。

场风、本场和供托在 OCR 分数不足时可使用经核对的文字模板，模板阈值为 0.98；模板与可信 OCR 冲突时输出未知。文字缓存只复用同一模型实例下像素、字段、阈值完全相同的结果，最多保留 64 项，修改返回值不会污染缓存。按钮可点击状态必须来自单独标注的状态模板，不能只凭按钮可见推断。

评估器按独立 `test` 对局统计检测召回、牌种准确率、赤牌、副露类型与来源、文字、按钮以及完整局面正确率，另验证不确定画面是否暂停。不确定图需人工指定 `expected_pause_regions`；这些区域必须报告不完整，不能仅靠配置未校准或按钮模板缺失得到“暂停通过”。同一对局泄漏或重复原图会拒绝评估。建议的数据量、37 类、四方向和专项覆盖不足时，报告保持 `gate_passed=false`，退出码为 3。

模板命令示例写入独立的 v3 `example` 库；需要使用自建库时，将其路径写入配置的 `templates`，移除或替换不兼容的 `classifier_manifest`。默认配置使用已准备的 v4 特征 `steam-default-v5` 库。Python 构建接口可显式指定 `feature_version=HIGHLIGHT_FEATURE_VERSION`；旧库不就地升级。
