# 首选领先补充接受规则（draft-24）

2026-10-16。按用户提议，把“首选超过 50%，且明显领先其他类别”量化为首选严格大于 0.5，且至少是第二名的 3 倍。第二名已经是其余所有类别的最大值，因此无需逐项比较剩余 33 类。此处是认牌模型原始 softmax 分数，不是界面候选操作的 Q 值相对百分比，也未经正确率校准。

## 行为与配置

保留原主路径 `top1 >= 0.9 && top1 - top2 >= 0.04`，增加补充路径 `top1 > 0.5 && top1 >= 3 * top2 && top1 - top2 >= 0.04`。例如 55% 对 15% 可接受，55% 对 30% 不接受，恰好 50% 不接受。

配置在两个默认文件的 `tile_classifier.dominant_candidate`：

```json
{"minimum_confidence": 0.5, "minimum_ratio": 3.0}
```

删除该配置项或设为 `null` 可恢复旧门槛。倍数必须大于 1，首选门槛可在 [0.5,1) 内配置。两种输入视角的分数不是同一个分布，补充路径比较所选视角内部的类别；原有两个视角均过 0.9 时的冲突检查保留。赤五颜色、横牌朝向、几何、副露分组、四张数量上限和规则动作校验继续执行。

日志 `pjura_evidence.class_acceptance` 记录规则、第二名分数和倍数。完整证据缓存绑定当前规则。原来适用横牌字形投票校验的牌继续先做该校验，不能因为补充路径提前接受而跳过；公开横放四索样例中，ViT 首选七索，已有一致字形校验会恢复正确四索，这条优先级保留。混合精度模型在新分数/倍数边界附近回到原 FP32 复核；没有更换或微调模型、没有改动用户已修复的 `app/vision/actions.py`。


[report.json](report.json) 保存时间、代码/模型哈希、两种模型单牌对照、三帧的六个尺寸场景及全部副露对照。立直牌河旧回归帧的两个尺寸也均保留建议。场景的完整识别、建议与耗时保存在同目录 JSON 中。程序测试结果另见 [tests.xml](tests.xml)。

最终完整测试 **628 项通过**（95.95 秒），无失败或跳过。覆盖严格 50% 边界、3 倍边界、配置与缓存、原精度复核、用户截图、赤五、横牌字形优先级和原有规则/界面回归。
